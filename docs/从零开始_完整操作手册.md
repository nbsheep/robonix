# 从零开始：M3E 无人机接入 RoboNIX 完整操作手册

> 本文是给**第一次上手**的人看的傻瓜版教程。每一步都写清楚：
> **在哪个窗口操作 → 敲什么命令 → 应该看到什么结果 → 看到别的结果怎么办。**
>
> 目标：让大疆 Mavic 3 Enterprise（M3E）无人机，最终能被 RoboNIX 用「原语」控制。
>
> 当前已知的 RC Pro 真实 IP：`10.225.57.15`（你家的网络可能会变，见第 3 步如何自己查）。

---

## 0. 先搞清楚两个「终端」（这是最容易搞混的地方）

你电脑上有 **两个完全不同的命令行窗口**，别搞混：

| | 窗口长什么样 | 怎么打开 | 用什么命令 | 简称 |
|---|---|---|---|---|
| **① Windows 命令行** | 标题栏写 `PowerShell` 或 `命令提示符`，路径是 `C:\Users\nice>` | 按 `Win` 键，输入 `powershell` 回车 | `python`、`curl.exe`、`wsl` | **Windows 侧** |
| **② Ubuntu（WSL2）** | 打开后是绿色的 `nice@xxx:~$` 提示符 | 在①里敲 `wsl` 回车；或开始菜单搜 `Ubuntu` | `python3`、`rbnx`、`cd ~/my-robot` | **Ubuntu 侧 / WSL2 侧** |

**一句话记住：**

- 想直接连无人机、跑 REPL 手动测试 → 在 **① Windows 命令行** 敲（快，不用 RoboNIX）。
- 想让 RoboNIX 真正接管、注册原语 → 在 **② Ubuntu** 敲（慢，但这是最终目标）。

> ⚠️ 同一个命令在不同窗口里写法不一样：
> - Windows 里 Python 叫 `python`；Ubuntu 里叫 `python3`。
> - Windows 里路径是 `C:\...`；Ubuntu 里访问你的 C 盘是 `/mnt/c/...`。

## 1. 整体流程一张图

```
你的电脑 (Windows 11)
│
├── ① Windows 命令行（PowerShell）
│       │ 第3步 验证链路:  curl.exe http://10.225.57.15:8080/api/status
│       │ 第4步 手动REPL:  python drone_bridge\main.py
│       │
│       └── 敲 wsl 进入 ↓
│
├── ② Ubuntu (WSL2)
│       │ 第5步 同步代码:  cp -r /mnt/c/... ~/my-robot/primitives/drone_bridge
│       │ 第6步 改配置:    nano ~/my-robot/robonix_manifest.yaml
│       │ 第7步 构建:      bash scripts/build.sh
│       │ 第8步 启动:      rbnx boot
│       │ 第9步 验证:      rbnx caps | grep drone
│
└── （通过 WiFi，同一局域网）
        │
        ▼
   RC Pro 遥控器 (Android, IP: 10.225.57.15)
        │  Drone_test APK → WebServer 端口 8080
        ▼
   M3E 无人机
```

**最小可行路线（推荐新手先走这条）：** 第 2 → 3 → 4 步就够了，全程只在 **① Windows 命令行** 操作，不碰 RoboNIX，先确认「电脑能控制无人机」这件事成立。然后再走 5～9 步把它接进 RoboNIX。

## 2. 开始前：检查清单

| # | 检查项 | 怎么确认 |
|---|--------|----------|
| 1 | 无人机 M3E 已开机 | 机臂灯亮、桨叶装好 |
| 2 | RC Pro 遥控器已开机、连上 WiFi | 遥控器下拉菜单看 WLAN，**和电脑同一个 WiFi** |
| 3 | RC Pro 上已打开 Drone_test APK | 屏幕停在「自动化飞行」页面 |
| 4 | 电脑和 RC Pro 在**同一个 WiFi** | 两个设备连同一个路由器 |
| 5 | 电脑上装了 Python（3.10+） | 在①里敲 `python --version` 有输出 |
| 6 | 电脑上装了 WSL2 + RoboNIX | 在②里敲 `which rbnx` 有输出（见第 5 步） |

## 3. 第一步：查 RC Pro 的 IP 地址（在遥控器上点）

这一步是为了拿到 IP，后面所有命令都要用它。

1. 在 RC Pro 上，从上往下划出下拉菜单 → 长按 `WLAN` → 连上和电脑相同的 WiFi。
2. 点已连的 WiFi 名字 → 看「IP 地址」一栏，记下来，通常是 `192.168.x.x` 或 `10.x.x.x`。
3. 现在你的真实 IP 是 `10.225.57.15`，**如果变了，把本文档所有 `10.225.57.15` 换成你的新 IP。**

> 更省事：打开 Drone_test APK 的「自动化飞行」页面，屏幕**底部会直接显示** `Web控制: http://<你的IP>:8080`，照抄那个 IP 就行。

---

## 4. 第二步：验证电脑能不能连上无人机（① Windows 命令行）

**干什么：** 只发一个「查状态」请求，不控制飞机，绝对安全。确认网络通不通。

**操作：** 打开 ① Windows 命令行（`Win` → 输入 `powershell` → 回车），敲：

```powershell
curl.exe http://10.225.57.15:8080/api/status
```

> 为什么加 `.exe`：PowerShell 里 `curl` 是另一个命令的别名，加 `.exe` 才调真正的 curl。用 `Invoke-RestMethod http://10.225.57.15:8080/api/status` 也可以。

**应该看到（一大段 JSON，关键字段）：**

```json
{
  "sdkRegistered": true,
  "productConnected": true,
  "missionState": "IDLE",
  ...
}
```

**结果判断：**

| 看到什么 | 含义 | 下一步 |
|----------|------|--------|
| 一大段 JSON，`sdkRegistered` 和 `productConnected` 都是 `true` | ✅ 全通了 | 继续第 5 步 |
| JSON 有返回，但 `productConnected:false` | APK 起来了，但飞机没连上 | 检查飞机是否开机、是否对频 |
| 报错 `Could not resolve host` / 超时 / 连不上 | ❌ 网络不通或 APK 没启动 | 看下面排查 |

**连不上的排查顺序（从上往下查）：**

1. RC Pro 的 WiFi 连了没？和电脑同一个网吗？
2. Drone_test APK 打开了吗？停在「自动化飞行」页面吗？
3. IP 抄对了吗？（第 3 步重新查）
4. 电脑上能 ping 通吗：`ping 10.225.57.15`（能看到「来自 10.225.57.15 的回复」说明通）

---

## 5. 第三步：用 REPL 手动测试原语（① Windows 命令行）

**干什么：** 不经过 RoboNIX，直接用一个交互式命令行（REPL）测试「查电量」「查位置」这些安全命令，验证映射关系对不对。

**操作：** 在 ① Windows 命令行，先进入项目目录再跑：

```powershell
cd C:\Users\nice\Desktop\drone_bridge
python drone_bridge\main.py
```

> 注意是 `python` 不是 `python3`；路径用反斜杠 `\`。

**应该看到：** 出现一个 `drone>` 提示符，进入交互模式。

**敲几个安全命令试试：**

```
drone> status        ← 回车，看完整状态
drone> bat           ← 查电量
drone> pos           ← 查位置
drone> q             ← 退出
```

**应该看到（示例）：**

```
drone> bat
{"percent": 87.0, "voltage": 16800.0}

drone> pos
{"latitude": 31.2..., "longitude": 121.5..., "altitude": 0.0, "heading": 0.0}
```

> ⚠️ **绝对不要在室内敲 `takeoff` / `land` / `move` / `gimbal` / `photo`**，它们会让飞机真的动！这些只能在室外空旷地、飞机已起飞准备就绪时测。

**到这里为止，你已经证明「电脑 → RC Pro → 无人机」这条链路是通的。** 接下来才是把它接进 RoboNIX。

---

## 6. 第四步：进入 Ubuntu（WSL2）

**干什么：** 从 Windows 命令行切到 Ubuntu 环境，RoboNIX 就装在 Ubuntu 里。

**操作：** 在 ① Windows 命令行敲：

```powershell
wsl
```

**应该看到：** 提示符变成绿色的 `nice@你的电脑名:~$`，说明已经进入 Ubuntu。

**先确认 RoboNIX 装好了：**

```bash
which rbnx
```

**应该看到：** `/home/nice/.cargo/bin/rbnx`

如果显示「找不到 rbnx」（`rbnx not found`），先执行：

```bash
export PATH="$HOME/.cargo/bin:$PATH"
which rbnx
```

> 提示：这个 `export` 每次新开 Ubuntu 窗口可能都要敲一次。嫌麻烦可以把它写进 `~/.bashrc`（见文末附录 A）。

---

## 7. 第五步：把最新代码同步进 Ubuntu

**干什么：** 你平时在 Windows 的 `C:\Users\nice\Desktop\drone_bridge` 改代码，Ubuntu 里那份是旧的，要重新拷一遍。

**操作：** 在 ② Ubuntu 里敲（`/mnt/c/` 就是你的 C 盘）：

```bash
mkdir -p ~/my-robot/primitives
rm -rf ~/my-robot/primitives/drone_bridge
cp -r /mnt/c/Users/nice/Desktop/drone_bridge ~/my-robot/primitives/drone_bridge
```

**应该看到：** 没有报错，命令直接结束（`cp` 成功不打印东西）。

**确认拷进去了：**

```bash
ls ~/my-robot/primitives/drone_bridge
```

**应该看到：** `README.md`、`drone_bridge/`、`scripts/`、`capabilities/`、`docs/`、`model/`、`web/` 等一堆文件。

---

## 8. 第六步：确认配置文件里的 IP 正确

**干什么：** 告诉 RoboNIX「无人机桥接的 IP 和端口是多少」。

**操作：** 在 ② Ubuntu 里看部署清单：

```bash
cat ~/my-robot/robonix_manifest.yaml
```

**应该看到一段包含：**

```yaml
primitive:
  - name: drone_bridge
    path: ./primitives/drone_bridge
    config:
      rc_pro_ip: "10.225.57.15"     ← 这里必须是你的真实 IP
      rc_pro_port: 8080
```

**如果 IP 不对，改它：**

```bash
nano ~/my-robot/robonix_manifest.yaml
```

用方向键移到 `rc_pro_ip` 那一行，改成你的 IP；改完按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

> 如果你的 `~/my-robot/robonix_manifest.yaml` 根本不存在，就把项目里自带的参考清单拷过去：
> ```bash
> cp ~/my-robot/primitives/drone_bridge/robonix_manifest.yaml ~/my-robot/robonix_manifest.yaml
> ```
> 然后再按上面改 IP。

---

## 9. 第七步：构建 codegen（生成 gRPC 桩）

**干什么：** 把 `capabilities/` 里的原语定义，编译成 Python 能直接调用的代码。不改代码就不用每次做，但**改完原语定义后必须重跑一次**。

**操作：** 在 ② Ubuntu 里：

```bash
cd ~/my-robot/primitives/drone_bridge
bash scripts/build.sh
```

**应该看到：**

```
[drone_bridge] rbnx codegen...
[drone_bridge] codegen 完成
```

**如果看到：**

```
[drone_bridge] ⚠ rbnx 未安装，跳过 codegen
```

说明 `rbnx` 没在 PATH 里，先 `export PATH="$HOME/.cargo/bin:$PATH"` 再重跑。

---

## 10. 第八步：启动 RoboNIX（rbnx boot）

**干什么：** 一键拉起 RoboNIX 的 atlas / executor / liaison 等核心组件，并自动启动 drone_bridge 原语。

**操作：** 在 ② Ubuntu 里，**先回到 my-robot 目录**再启动：

```bash
cd ~/my-robot
export PATH="$HOME/.cargo/bin:$PATH"
rbnx boot
```

**应该看到（会打印一个 RoboNIX 的 ASCII logo，然后）：**

```
✓ 4 component(s) up; logs under /home/nice/my-robot/rbnx-boot/logs
```

> ⚠️ 一定要 `cd ~/my-robot` 再 `rbnx boot`，否则报 `manifest not found`。

---

## 11. 第九步：验证 drone_bridge 已注册（12 个原语）

**干什么：** 确认无人机原语成功注册进 RoboNIX。

**操作：** 在 ② Ubuntu 里（另开一个窗口，或先 `Ctrl+C` 不停也行，见下注）：

**① 看日志有没有连上 RC Pro：**

```bash
cat ~/my-robot/rbnx-boot/logs/drone_bridge.log
```

**关键几行：**

```
[drone_bridge] RC Pro: 10.225.57.15:8080
[drone_bridge] ✅ 已连接到 RC Pro (http://10.225.57.15:8080)
registered primitive 'drone_bridge'
state INACTIVE -> ACTIVE
```

**② 看注册的能力列表：**

```bash
export PATH="$HOME/.cargo/bin:$PATH"
rbnx caps | grep drone
```

**应该看到：**

```
● drone_bridge [ACTIVE] robonix/primitive/drone (12 caps)
```

**③ 看每个能力明细：**

```bash
rbnx describe --provider drone_bridge
```

**应该看到 12 个能力：**

```
● drone_bridge [ACTIVE]
    └─ robonix/primitive/drone/driver (grpc)
    └─ robonix/primitive/drone/takeoff (grpc)
    └─ robonix/primitive/drone/land (grpc)
    └─ robonix/primitive/drone/move_ee (grpc)
    └─ robonix/primitive/drone/hover (grpc)
    └─ robonix/primitive/drone/rth (grpc)
    └─ robonix/primitive/drone/move_relative (grpc)
    └─ robonix/primitive/drone/gimbal_rotate (grpc)
    └─ robonix/primitive/drone/camera_capture (grpc)
    └─ robonix/primitive/drone/camera_zoom (grpc)
    └─ robonix/primitive/drone/state_position (grpc)
    └─ robonix/primitive/drone/state_battery (grpc)
```

> 注：`rbnx boot` 是前台阻塞的，会一直占着那个窗口。要看日志/跑 `rbnx caps`，**另开一个 Ubuntu 窗口**敲即可；或者用 `Ctrl+C` 停掉 boot（但那样原语也停了）。

## 12. 第十步：真正调用原语（室外安全时）

到这一步，无人机原语已经进 RoboNIX 了。真正的飞行调用有三条路：

| 方式 | 在哪操作 | 适用 |
|------|----------|------|
| 网页控制台 | 电脑浏览器打开 `http://10.225.57.15:8080` | 日常最直观，看视频+遥测 |
| REPL 手动 | ① Windows 命令行 `python drone_bridge\main.py` | 快速调试 |
| RoboNIX 原语 | 上层 skill / gRPC 调用 `robonix/primitive/drone/takeoff` 等 | 最终集成（要再写 skill 层） |

**户外实测顺序（务必先在空旷低空、有人看护）：**

1. `takeoff` 起飞悬停 → 2. `move_relative` 相对移动 → 3. `gimbal_rotate`/`camera_capture` 云台相机 → 4. `hover`/`rth`/`land` 安全兜底。

具体每个原语怎么调、参数怎么填、判据是什么，见 **`docs/primitive_calling_guide.md`**。

## 13. 完整命令速查表

### ① Windows 命令行（PowerShell）

```powershell
# 查 IP 是否通（验证链路）
curl.exe http://10.225.57.15:8080/api/status

# 用 Invoke-RestMethod 也行（自动格式化 JSON）
Invoke-RestMethod http://10.225.57.15:8080/api/status

# 手动 REPL
cd C:\Users\nice\Desktop\drone_bridge
python drone_bridge\main.py

# 进 Ubuntu
wsl
```

### ② Ubuntu（WSL2）

```bash
# 每次进 Ubuntu 先让 rbnx 可用（找不到再敲）
export PATH="$HOME/.cargo/bin:$PATH"

# 同步最新代码
rm -rf ~/my-robot/primitives/drone_bridge
cp -r /mnt/c/Users/nice/Desktop/drone_bridge ~/my-robot/primitives/drone_bridge

# 看/改配置
cat ~/my-robot/robonix_manifest.yaml
nano ~/my-robot/robonix_manifest.yaml

# 构建 codegen
cd ~/my-robot/primitives/drone_bridge && bash scripts/build.sh

# 启动 RoboNIX
cd ~/my-robot && rbnx boot

# 验证（另开一个 Ubuntu 窗口）
cat ~/my-robot/rbnx-boot/logs/drone_bridge.log
rbnx caps | grep drone
rbnx describe --provider drone_bridge

# 停止 RoboNIX（清理旧进程）
pkill -f robonix
```

## 14. 常见报错速查

| 现象 | 原因 | 解决 |
|------|------|------|
| `curl` 连不上 / 超时 | APK 没开、WiFi 不对、IP 抄错 | 回第 3、4 步重查 |
| JSON 里 `productConnected:false` | 飞机没连上 RC Pro | 飞机开机、重新对频 |
| `bat` 返回 `percent:0` | 飞机没连，读不到电池组件 | 确认 `productConnected:true` |
| `pos` 返回 `latitude:null` | 室内无 GPS 信号 | 到室外开阔地再测 |
| `rbnx: command not found` | PATH 没设 | `export PATH="$HOME/.cargo/bin:$PATH"` |
| `rbnx boot` 报 `manifest not found` | 没在 `~/my-robot` 目录下 | `cd ~/my-robot` 再跑 |
| `rbnx boot` 报端口占用 | 上次没退干净 | `pkill -f robonix` 再跑 |
| `rbnx caps` 没有 drone_bridge | manifest 没配 / 没拷进 Ubuntu | 回第 6、7 步 |
| 日志显示连不上 RC Pro | WSL2 网络隔离 | 见第 15 步 |
| `build.sh` 说 rbnx 未安装 | PATH 问题 | `export PATH=...` 后重跑 |

## 15. WSL2 连不上 RC Pro 怎么办

Windows 和 RC Pro 在同一个 WiFi，能直接通；但 **Ubuntu（WSL2）默认是另一套 NAT 网络，可能访问不到 RC Pro**。

**判断：** 在 ① Windows 命令行 `curl.exe http://10.225.57.15:8080/api/status` 能通，但 ② Ubuntu 里 `curl http://10.225.57.15:8080/api/status` 不通 → 就是这个问题。

**三个办法，按推荐顺序：**

**办法 A（最简单）：bridge 直接跑在 Windows 侧**
- 反正第 4 步已经证明 Windows 能连，那就别用 WSL2 跑 bridge，直接用 Windows 跑 REPL（第 5 步）即可。缺点是没进 RoboNIX。

**办法 B：WSL2 改桥接网络**
- 在 ① Windows 命令行（管理员）编辑 `%USERPROFILE%\.wslconfig`，加：
  ```
  [wsl2]
  networkingMode=bridged
  ```
- 然后 `wsl --shutdown` 再重新 `wsl`。

**办法 C：确认 WSL2 网络（其实很多时候能通）**
```bash
# 在 ② Ubuntu 里
curl http://10.225.57.15:8080/api/status
# 如果通，就不用管，直接 rbnx boot 即可
```

## 附录 A：让 rbnx 每次进 Ubuntu 自动可用

不想每次敲 `export PATH=...`，就把它写进启动文件（在 ② Ubuntu 里敲一次）：

```bash
echo 'export PATH="$HOME/.cargo/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

以后新开的 Ubuntu 窗口都能直接 `rbnx`。
